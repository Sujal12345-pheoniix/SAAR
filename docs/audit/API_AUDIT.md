# SAAR API Architecture & Contract Audit

**Author:** Principal Software Architect & API Auditor  
**Date:** September 2026  
**Repository Source of Truth:** `SAAR — Personal Growth Intelligence Platform` (`saar`)  
**Scope:** RESTful API Design, Request/Response Envelopes, DTO vs Zod Contract Alignment, Error Normalization, Client Integration  

---

## 1. Executive Summary

The SAAR backend exposes a REST API powered by NestJS 10.4.4 with an Express HTTP adapter and a global versioning prefix (`/api/v1`). The API surface covers 10 controllers and 51 distinct routes.

Our forensic audit discovered significant **contract drift** between the shared `@saar/contracts` package (which defines schemas in Zod) and the NestJS API implementation (which duplicates validation rules using `class-validator` DTOs). Furthermore, critical routing mismatches exist between the backend API and frontend clients (most notably in mobile authentication), and automated OpenAPI/Swagger documentation is entirely missing.

---

## 2. API Design & RESTful Standards Compliance

### 2.1 Route Prefixing & Versioning Inconsistency
- In `apps/api/src/main.ts:25`, the global prefix is configured:
  ```typescript
  app.setGlobalPrefix('api/v1', {
    exclude: ['health', 'auth/(.*)'], // Auth routes excluded from api/v1 prefix
  });
  ```
- **Architectural Consequence:**
  - Auth endpoints are routed as `/auth/login`, `/auth/register`, `/auth/refresh`.
  - Business domain endpoints are routed as `/api/v1/users/me`, `/api/v1/tasks`, `/api/v1/goals`.
  - **Client Confusion:** The mobile client assumes all endpoints are prefixed uniformly or attempts to call `/auth/me` without understanding that user identity is under `/api/v1/users/me`.

### 2.2 Missing OpenAPI / Swagger Specification
- Neither `@nestjs/swagger` nor `swagger-ui-express` is installed in `apps/api/package.json`.
- There is **no OpenAPI specification file (`openapi.json` / `openapi.yaml`)** generated or committed to the repository.
- **Impact:** Frontend and mobile developers cannot automatically generate typed API clients, leading directly to human contract mismatches (such as `P0-MOB-001`).

## 3. Contract Drift: Zod vs `class-validator`

The monorepo contains a dedicated package: `packages/contracts`.
- In `packages/contracts/src/auth.ts`:
  ```typescript
  export const LoginRequestSchema = z.object({
    email: z.string().email(),
    password: z.string().min(8),
  });
  export type LoginRequest = z.infer<typeof LoginRequestSchema>;
  ```
- In `apps/api/src/modules/auth/dto/login.dto.ts`:
  ```typescript
  export class LoginDto {
    @IsEmail()
    email: string;

    @IsString()
    @MinLength(8)
    password: string;
  }
  ```
- **Architectural Duplication & Drift:**
  1. The API duplicates every Zod contract into manual TypeScript classes decorated with `class-validator`.
  2. Over time, validations have diverged: for example, `TaskCreateSchema` in `contracts` allows optional `notes` and `estimatedMinutes`, while `create-task.dto.ts` omits `estimatedMinutes`.
  3. Clients importing `@saar/contracts` send fields that the API's `ValidationPipe({ forbidNonWhitelisted: true })` rejects with HTTP 400 `property estimatedMinutes should not exist`.

## 4. Error Normalization & Response Envelopes

### 4.1 Global Exception Filter (`http-exception.filter.ts`)
The API uses a standardized exception filter:
```typescript
{
  "statusCode": 400,
  "message": "Validation failed",
  "errors": ["email must be an email"],
  "timestamp": "2026-09-25T14:30:00.000Z",
  "path": "/auth/login",
  "requestId": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d"
}
```
- **Strengths:** Includes `requestId` generated by `request-id.interceptor.ts`, consistent timestamp, and RFC 7807 compliant structure.
- **Defects:** Unhandled 500 internal server exceptions occasionally leak database driver stack traces in non-production environments without redaction.

### 4.2 Idempotency Deficiencies
- High-stakes mutating endpoints (e.g., `POST /api/v1/behavior-events`, `POST /api/v1/routines/:id/complete`) lack `Idempotency-Key` header support.
- If a mobile client encounters network retry behavior in offline/flaky network transitions, duplicate behavior events and duplicate streak counts are recorded.

---

## 5. Remediation Roadmap

1. **Install `@nestjs/swagger`:** Document all 51 endpoints and generate an automated `openapi.yaml` during CI builds.
2. **Unify Contracts:** Integrate `nestjs-zod` or generate DTOs directly from `@saar/contracts` Zod schemas to ensure 100% type and runtime validation symmetry.
3. **Normalize Auth Routes:** Expose standard `/api/v1/auth/*` routes and provide explicit backward-compatible rewrites for `/auth/*`.
4. **Implement Idempotency Middleware:** Intercept mutating requests with `Idempotency-Key` backed by Redis caching.
